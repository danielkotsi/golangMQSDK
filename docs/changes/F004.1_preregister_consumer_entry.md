# F-004.1 — Pre-register per-consumer entry in `Consume`

**Branch:** `dkotsi/MultipleConsumersPerChannel`  
**PR:** #2  
**Issue:** `docs/F-004.1.md` (OPEN → resolved by this change)

---

## Problem

The per-consumer entry was created in `route` when `basic.consume-ok`
arrived. Because the broker dispatches `basic.deliver` from a separate
`dispatchLoop` goroutine, the delivery can hit the wire before
`basic.consume-ok`. When it arrived first, the tag had no registered
entry, so the delivery fell through to the shared `ch.Incoming` — which
the `Consume` caller never reads. Pre-queued messages were silently
lost, intermittently (observed ~1-in-30 under `-race`).

The comment in `route` claiming serial `readLoop` processing made the
race impossible was wrong: arrival order across two broker goroutines is
non-deterministic.

## Fix (Option A from the issue)

The client already owns the consumer tag (`nextConsumerTag`), so the
entry is now created in `Consume`, under `ch.mu`, **before**
`basic.consume` is written:

- `Consume` allocates the per-consumer channel and registers it under
  the client-minted tag up front.
- Every early-failure path (write error, broker error, unexpected
  payload, `ctx.Done`) deletes the entry before returning.
- `route`'s `BasicConsumeOKType` case no longer creates the entry; it
  looks the pre-registered entry up and resolves the pending `Consume`
  with its channel.
- Legacy broker (empty echoed tag): `route` resolves with `nil`,
  `Consume` deletes the pre-registered entry and returns `ch.Incoming`,
  preserving v0.2.0 behaviour.
- The incorrect race comment was replaced with an accurate one.

### Files

- `gomqSDK/channels.go` — `Consume` pre-registration + cleanup;
  `route` consume-ok lookup; corrected comment.
- `gomqSDK/multiconsumer_test.go` — the stress test now echoes the
  actual requested tag (as the real broker does), plus a new
  `TestF004_DeliveryBeforeConsumeOKRoutesToPerConsumerChannel` that
  reproduces the F-004.1 ordering (deliver before consume-ok).

```

go vet ./...                        # ok

```

The new test sends `basic.deliver` before `basic.consume-ok` and asserts
the delivery lands on the per-consumer channel and never on `Incoming`.

## Scope

- SDK-only; the broker is correct. No broker change.
- Single-delivery guarantee preserved: pre-registration means a delivery
  routes to exactly one channel, never duplicated between `Incoming`
  and the per-consumer channel.
